# おいしい店マップ（非公式）

> 本アプリは個人が作成した非公式の地図です。食べログ（株式会社カカクコム）の公式サービスではなく、提携関係もありません。
> 評点・口コミ・写真は掲載していません。各店の詳細はリンク先の食べログでご確認ください。
> 営業時間・定休日・価格は変更される場合があります。お出かけ前に店舗の公式情報をご確認ください。
> 地図データ © OpenStreetMap contributors（ODbL）

公開URL: https://nerorisaia.github.io/oishii-map/

首都圏の「評判の根拠が公開情報で確認できる名店」だけを載せた地図です。2026-11-13 調査の69店に、2026-11-17 に東京都品川区・大田区の追加調査分362店を加えた計431店です。掲載店の選定と「根拠」の要約は作成者が公開情報をもとに行ったもので、食べログ・ミシュランガイド等の各サービスが本アプリを承認・推薦しているものではありません。

## 機能

- 掲載店を地図にフォークとナイフのピンで表示します。店舗データはページ（`index.html`）に同梱しており、外部 API は使いません。通信は地図タイル（OpenStreetMap）だけです。
- 現在地を取得し、現在地から近い順の一覧を表示します（現在地が無いときは地図の中心から近い順）。
- 現在地の追従は兄弟アプリ（喫煙所マップ・タイムズ駐車場マップ）と同じ仕様です。
  - 位置が届くたびに現在地へ地図を寄せます。
  - 地図を手で動かす（ドラッグ・ピンチ・ホイール・ダブルタップ・＋－ボタン・キー操作）と、手を離した時点から5秒間は追従を止め、5秒後に現在地へ戻ります。
  - 「最寄り」や一覧から店を選んだ直後は10秒間追従を止めます（その後の測位で追従に戻ります）。
  - 「現在地」ボタンを押すと、どちらの一時停止もすぐ解除して現在地へ戻ります。
- 絞り込み: ジャンルのチップと根拠タグのチップ。ジャンルとタグの間は AND、同じ種類の中は OR です。
- 店のピンまたは一覧をタップすると詳細カード（店名、エリア・最寄り駅、ジャンル、看板メニュー、根拠、最終確認日）を表示します。ボタンは「食べログで見る」（新しいタブ）と「Googleマップで案内」（公式の Maps URLs 形式 `https://www.google.com/maps/search/?api=1&query=緯度,経度`。地図画像の転載はしていません）の2つだけです。
- 食べログの評点・口コミ・店舗写真・ロゴ・バッジ画像はアプリに一切含めていません（リンクのみ）。
- スマホ（Android の Chrome）では「アプリをインストール」／「ホーム画面に追加」でアプリとして使えます（manifest: 名前「おいしい店マップ」、192px・512px アイコン、`display: standalone`）。
- Service Worker のキャッシュ名は `oishii-map-v3`（初版は v1）、スコープは `/oishii-map/` だけです。同じオリジンの他アプリのキャッシュには触りません。

## データの出典と時点（2026-11-13 調査）

| ファイル | 内容 |
|---|---|
| [`data/stores.txt`](data/stores.txt) | 掲載店リスト（店名｜エリア・最寄り駅｜ジャンル｜看板メニュー｜根拠｜食べログURL）。作成者が公開情報をもとに作成 |
| [`data/addresses.txt`](data/addresses.txt) | 各店の所在地。店舗公式サイト・自治体や観光協会の観光サイト・グルメ情報サイト等で、複数の公開情報が一致した住所 |
| [`data/coords.json`](data/coords.json) | 各店の座標、座標の出所（`source`: `osm` / `geocode`）、最終確認日（`checked`） |
| [`data/sources.txt`](data/sources.txt) | 追加調査分の各店について、根拠と住所を確認した出典URL |
| [`data/osm_manual.json`](data/osm_manual.json) | 住所が番地まで分からない店で、同じ店と手作業で確認した OpenStreetMap 要素（理由つき） |

座標の決め方（推測で座標を置かない）:

1. OpenStreetMap（Overpass API、データベース時刻 2026-11-13T02:50:34Z）で店名を検索し、該当する飲食店の地点を候補にする（`tools/fetch_osm.py`、検索語は `tools/match_terms.py`）。
2. 公開情報で特定した住所を座標にする（`tools/geocode.py`）。Nominatim を先に試しましたが、日本の住所では町名止まりか、街区番号と建物番号を取り違えた地点を返す例（銀座4-11-7 → 銀座4-5-11 の建物）を確認したため、座標には国土地理院「住所検索API」の結果のうち「〜番」「〜号」「〜番地」まで一致したものだけを使っています（Nominatim の結果は `nominatim_ref` として参考保存のみ）。
3. OSM と住所の座標の両方がある店は、2点の距離が 200m 以内なら OSM の座標（`source: osm`、`pair_distance_m` に距離）を使います。200m 以内に OSM 候補が無い店は住所の座標（`source: geocode`）を使います。住所が番地まで座標化できない店は、OSM 地点の住所タグが公開情報の住所と一致する場合だけ OSM の座標を使います。
4. 最後に Nominatim の逆ジオコーディングで座標の市区町村を取り、住所の市区町村と一致することを確認しています（`tools/resolve.py`、結果は `reverse` に保存）。

「根拠」には、根拠となった情報の年（選出年・受賞年・放送年・記事や資料の年など）を必ず書いています。年が出典で確かめられなかったものは、作成者が公開情報を確認した時点を「（2026年11月確認）」と書いています（受賞・選出の年ではありません）。大田区「OTA!いちおしグルメ」表彰店は、出典が大田区の2021年総合版のため「（2021年総合版に掲載）」としています。閉店・移転・休業など店舗に不利な情報は、店舗の公式発表か、信頼できる情報源2件以上で確かめられた場合だけ表示します。

根拠タグは「根拠」文から機械的に付けています（`tools/build.py` の `tags_of`）: 百名店／ミシュラン／Tabelog Award（その語を含む）、老舗（「老舗」「最古」「創業100年」「明治」を含む、または創業・開店・オープン・開業の年が50年以上前）、TV紹介（「TV紹介」を含む）、地元名物・ご当地（「公式」「観光協会」「発祥」「元祖」「名物」「ご当地」「代表店」を含む）、メディア紹介（「メディア紹介」、『誌名』、「Hanako」「Retty」を含む）。どれにも当てはまらない店はタグなしです。

## 品川区・大田区の追加調査（2026-11-17）

区×ジャンルで分担して公開情報を調べ、次の条件をすべて満たす店だけを候補にしました（件数を埋めるための追加はしていません）。

- 住所が品川区・大田区内で、食べログの店舗ページに閉店・移転・休業・掲載保留の表示がない
- 評判の根拠が公開情報で確認できる（食べログ百名店、ミシュランガイド東京、The Tabelog Award、TV番組の公式記録、区・観光協会・商店街連合会・産業振興協会の紹介や表彰、雑誌・Web媒体の特集、創業年）。評点の数字・口コミは根拠にしない
- 個人店・地元店を優先し、全国チェーンの支店は支店そのものに根拠がある場合だけ

調査の原票（8項目: 店名｜エリア・最寄り駅｜ジャンル｜看板メニュー｜根拠｜食べログURL｜住所｜出典URL）は作成者の手元にだけ置き、公開していません。候補は `tools/merge_candidates.py` で検査（項目数、食べログURLの形式、対象区の住所、評点らしき表現、既存店・保留リストとの重複）し、同じ店は根拠の多い方に統合しました。開店ニュース記事だけが根拠の店は外しています。根拠欄の年（例: ビブグルマン2016〜2020）は掲載・選出された年で、現在も選出中とは限りません。

## 店舗データの更新手順

原本フォルダ（LAN 版。このリポジトリの `tools/`・`src/`・`data/` と同じ構成に、LAN 用サーバー `tools/serve.py` と `public/` を加えたもの）で作業し、最後にこのリポジトリへ反映します。

1. `data/stores.txt` に1行追記します（区切りは全角の「｜」、6項目）。
   ```
   店名｜エリア・最寄り駅｜ジャンル｜看板メニュー｜根拠｜https://tabelog.com/…/
   ```
   ジャンルが新しい場合は `tools/build.py` の `GENRE_GROUPS` にチップを追加します（未定義だとビルドが止まります）。
2. `data/addresses.txt` に `店名｜住所` を追記します（公式サイト等の公開情報で確認した所在地）。`tools/match_terms.py` に店名の検索語（表記ゆれ）を追加します。
3. 座標を求めて確認します。
   ```
   python -I tools/fetch_osm.py data/raw/osm_candidates.json
   python -I tools/geocode.py
   python -I tools/resolve.py
   ```
   `resolve.py` の出力で、各店の出所・距離・逆ジオコーディング結果を確認します。「未確定」になった店は地図に載りません（推測で座標を足さないでください）。旧店舗など別地点と分かった OSM 要素は、原本フォルダの `data/osm_exclude.json`（公開しない内部ファイル）に追加します。
4. `data/coords.json` の `checked`（`tools/resolve.py` の `CHECKED`）を確認日に更新します。
5. `src/sw.js` の `CACHE` の番号を上げます（今は `oishii-map-v3`）。
6. ビルドします。
   ```
   python -I tools/build.py                                            # LAN 版（public/）
   python -I tools/build.py --out ../oishii-map-public --scope /oishii-map/   # 公開版（このリポジトリ）
   ```
   Git Bash で実行する場合は `/oishii-map/` がパスに変換されないよう、先頭に `MSYS_NO_PATHCONV=1` を付けます。
7. `python -I tools/export_public.py ../oishii-map-public` で `data/` を書き出し（地図に載せていない店・除外リスト・調査原票・保留リストは書き出しません）、`tools/`・`src/` をこのリポジトリへコピーし、commit して push します（GitHub Pages に自動で反映されます）。
